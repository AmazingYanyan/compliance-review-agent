### 关键踩坑（有长期价值）
- **TanStack Router 扁平命名 vs 目录结构**：`parent.$param.child.tsx` 这种 `.` 扁平命名会把 child 变成 parent 的**子路由**（嵌套）。若 parent 组件没有 `<Outlet/>`，子路由内容不渲染（URL 对、matchRoutes 对，但渲染的是 parent 组件）。要"父路径 + 子路径是独立页面"，必须用目录结构：`parent.tsx`（纯 Outlet layout）+ `parent/index.tsx`（列表页）+ `parent/$param.child.tsx`（子页面）。
- **routeTree.gen.ts 是 codegen 自动生成的**，手改会被 vite build 覆盖；改路由文件结构后需重新触发 codegen（`bunx vite build` 跳过 tsc，或直接构建）。
- **浏览器自动化**：WorkBuddy 浏览器插件（`mcp__browser`，browser_id=2 是用户 Chrome）可直接操作已登录 Chrome，含截图/点击/输入/DOM 快照，但**无 JS eval 能力**；agent-browser（`npx -y agent-browser@latest`）有 `eval`/`console`/`errors`，但独立浏览器无登录态、会话易失。诊断前端路由问题最有效的组合：agent-browser 的 `window.__TSR_ROUTER__` 直接查 `matchRoutes()`/`routesById`/`routesById[x].fullPath`。
