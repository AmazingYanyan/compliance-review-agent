# 章程核对工作台 · 浏览器验收流程

## 前置

- 工作目录：仓库根目录（`v2/workbench` 分支）。
- 只用静态预览，不启后端；阶段 B 的接口与数据库验收不在本流程内。
- 端口占用时改用其他端口（例如 8093），命令里的 `--directory credit-review-app-v2/prototype` 保持不变。

## 启动

```bash
python3 -m http.server 8092 --bind 127.0.0.1 --directory credit-review-app-v2/prototype
```

浏览器打开 <http://127.0.0.1:8092>。无构建步骤、无依赖。

## 验收步骤与预期结果

1. **顶部任务与状态条**：显示任务名、客户角色、状态徽标、「已确认 N / M」、输入版本号；「完成核对」在该区域内。
2. **六种场景**：用「评审场景」下拉依次切换 正常核对 / 处理中 / 缺材料 / 覆盖不全·无效出处 / 覆盖不全·输出截断 / 已完成只读。预期每种状态的横幅、卡片集合与完成入口状态都不同；两个覆盖不全场景的受影响项集合不同。
3. **受影响项标记**：覆盖不全场景中受影响卡片有状态竖条与「受影响 · 无效出处」或「受影响 · 输出截断」标签，横幅列出受影响项标题；其余摘录仍可接受或拒绝。
4. **完整路径**：点「下一条待办」→ 应聚焦到当前项之后的首个未处理项、跳过已处理项、到末尾回绕；点「查看出处 · 第 N 页」→ 左侧跳页并高亮、页码显示已定位页；点「拒绝」→ 出现原因框且自动聚焦，留空（含纯空格）时「保存拒绝」禁用，填入文本后可保存；点「接受」→ 计数 +1；全部处理后「完成核对」可用，完成后刷新仍显示历史决定与拒绝原因，且无决定入口。
5. **完成入口原因**：不可完成时按钮禁用且旁边给出原因（覆盖不全 / 未确认 N 项 / 拒绝未填原因 M 项）；可用时提示「可完成」。
6. **原件控件**：左栏可上一页/下一页、输入页码、切换缩放档位（适应宽度/100%/150%/200%），并显示「原型边界：文字坐标线框，非真实 PDF 渲染」。
7. **演示态声明**：界面标明决定保存在浏览器本地，阶段 B 以 V2 接口与数据库为准。
8. **控制台**：整轮操作无报错。

## 一致性检查

同一浏览器窗口尺寸下切换六种场景，字号、间距、表格密度、状态色与按钮层级保持一致（全部来自 `workbench.css` 的共用变量）。

## 边界

- 第 14、15 页是文字坐标线框，不是真实 PDF 渲染；缩放、定位与高亮精度在阶段 B 用本地批准样本验证。
- 决定存储为浏览器本地存储，阶段 B 改为接口与数据库。
- 营业执照与审计财报页签只显示「后续迁移范围」提示，本流程不验收其核对能力。
