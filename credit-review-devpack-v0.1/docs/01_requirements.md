## 1. 一期目标与交付

以流动资金贷款的资料完整性检查为首个小场景。业务人员统一上传资料后，系统调用已有 OCR 服务获取文字、表格、印章／签名裁剪图及坐标，使用大模型识别材料类别，并按照固定清单查找、摘取相关原文及对应印章／签名图像。业务人员在网页中对照原件，对每条结果接受或拒绝；全部结果完成选择且拒绝原因填写完整后，结束本次核对。

现有Figma为可编辑、可交互网页原型；本轮交付为详细软件需求及配套本地Agent开发材料，不是已实现的网站。Figma 中的资料、条款、企业与金额均为虚构示例，不作为业务规则来源。

最终方向是 AI 辅助判断；一期先完成原文摘录与人工核对。AI 可以做材料分类、相关性匹配、摘录排序，以及印章／签名的内容识别和检查项匹配，不输出审批权限、表决比例适用性、材料合规性等推理结论。即使找到章程条款，一期也不根据本笔贷款金额推断应由哪个机构批准。

## 2. 已确认的范围

| 事项 | 一期约定 |
| --- | --- |
| 使用方式 | 网页端，围绕对公信贷语境 |
| 用户 | 最多5人同时使用；多用户登录，不同账号的任务、文件、识别结果与人工确认记录互不可见 |
| 客户类型 | 本期只启用借款人；保证人、抵（质）押人可见但置灰不可点击；分别预留独立清单与版本配置 |
| 产品 | 仅流动资金贷款，产品选项可预留扩展 |
| 材料 | 营业执照、公司章程、最近一年已审计财报 |
| 输入 | 多文件统一上传，PDF、JPG、PNG |
| 分类粒度 | 一个文件对应一种材料，不做混合文件按页拆分 |
| 分类依据 | AI 根据 OCR 内容识别，允许用户纠正分类 |
| 结果 | 原文文字、OCR HTML 表格、印章／签名识别文字与裁剪图，或对应“未找到”结果 |
| 编辑限制 | 一期不可修改、补写摘录；可接受、拒绝并填写拒绝原因 |
| 人工确认粒度 | 每段独立确认；每张完整表格、每个印章／签名候选分别作为一条结果确认；一个候选的识别文字与图片共用一组确认 |
| 完成条件 | 所有结果已选择接受或拒绝，且每条拒绝原因非空 |
| 结束方式 | 保存并在当前页提示核对完成，无单独结果汇总页 |
| 保存 | 任务、文件、识别与人工确认结果需要持久化 |
| 任务入口 | 首页新建／继续、我的任务列表；资料核对与材料管理顶部可直接切换当前账号的任务 |

后续扩展包括整份源文件视觉理解辅助材料分类、混合文件拆分、AI 辅助判断。本版允许印章／签名裁剪图的定向视觉识别，不代表启用整份源文件视觉分类。本期不做财务指标分析、逐单元格确认、原文编辑及自动授信决策。

## 3. 固定搜寻清单

固定清单是右侧页面的结构来源，可用树形 JSON 表达。一期由系统按产品及法人客户类型分别预置，不建设清单管理后台。每个叶子检查项可以返回零到多条摘录；没有找到时生成一条“未找到”结果，同样要求人工确认。

本节下表为现有借款人场景的示例基线。保证人与抵（质）押人的具体检查清单尚未提供；必须分别落实，不能复制借款人清单冒充已确认业务要求。V0.4原型曾启用后两种角色入口；V0.5覆盖为首页按钮置灰、不可点击，后端也禁止创建该角色的新任务。待配置属于系统业务配置缺失，不等同于材料未找到，也不能生成一批“未找到”供用户完成核对。三种角色真实检查能力的交付仍依赖后两种清单定稿。

| 材料 | 搜寻要点／问题 | 展示内容 |
| --- | --- | --- |
| 营业执照 | 经营范围 | 对应原文 |
| 营业执照 | 营业期限 | 对应原文 |
| 营业执照 | 登记状态 | 对应原文；未找到则提示，不从其他字段自行推断 |
| 公司章程 | 经营范围条款 | 对应原文 |
| 公司章程 | 借款与担保的决议权限 → 有权批准的是股东会还是董事会？ | 所有相关条款原文，按相关程度排列，不归纳为审批机构结论 |
| 公司章程 | 借款与担保的决议权限 → 需要多少表决权比例通过？ | 表决比例及其条件、例外对应原文，不判断其对本笔贷款的适用性 |
| 公司章程 | 对外担保的限制性规定 | 对应原文 |
| 公司章程 | 法定代表人的签字权限 | 对应原文 |
| 公司章程 | 股权结构与特殊条款 | 对应原文；存在多处时分别摘录 |
| 财报 | 报表所属企业 | 企业名称原文 |
| 财报 | 报告年度 | 年度／期间原文 |
| 财报 | 资产负债表 | 渲染完整的 OCR 表格，保留表头与单位等原文信息 |
| 财报 | 利润表 | 渲染完整的 OCR 表格 |
| 财报 | 现金流量表 | 渲染完整的 OCR 表格 |
| 财报 | 审计机构 | 对应机构名称的原文 |
| 财报 | 审计单位印章 | 识别文字、对应印章裁剪图及出处；多候选独立展示 |
| 财报 | 注册会计师签名 | 识别文字、对应签名裁剪图及出处；多候选独立展示 |
| 财报 | 审计意见 | 直接表达审计意见的必要原文段落，保留影响含义的限定语 |

不设置笼统的“审计报告内容”摘录项，避免摘录整篇报告。现有借款人示例清单有18个叶子检查项；原型包含19条示例结果，因为“批准机构”示例找到了两段相关条款。营业执照3条、公司章程7条、财报9条。实际结果数量由客户类型、材料及候选数量决定，不能写死为19。

“最近一年”的年度计算方式尚未单独确认。原型以2025年度为示例；开发前需确定按自然年度、业务申请日期还是其他业务口径判断，不能把示例年度固化成规则。

## 4. 上传、识别与纠正分类

### 4.1 正常流程

1. 登录后进入首页，点击或拖拽批量上传文件，选择已启用的借款人。本期产品为流动资金贷款，另外两种客户类型置灰。
2. 点击“开始核对”，校验至少有一份有效文件且已选客户类型；直接进入该任务的核对工作台，不增加中间页面。上传、OCR、分类和摘录未完成时在工作台显示加载动画及当前阶段，材料管理保留文件级状态。清单未配置则显示配置缺失，不能进入假检查流程。
3. OCR 返回各页文字、HTML 表格、段落／表格坐标及页面尺寸，并提供已检测的印章／签名裁剪图（如 Base64）及可用的识别文字、来源信息；字段和实际能力需联调确认。
4. AI 根据 OCR 内容识别材料类别，按当前任务产品与客户类型对应的清单查找相关内容。
5. 系统按营业执照、公司章程、财报组织材料导航，在同一个左右工作区内切换显示。
6. 用户逐条核对、接受或拒绝，最后点击“完成核对”。

### 4.2 分类异常

| 情况 | 处理 |
| --- | --- |
| AI 判断类别错误 | 用户选择正确类别；按修正类别重新执行对应搜寻任务 |
| 不能确定唯一类别 | 提示检查文件，拆分或更换后重新上传，不强制归类 |
| 确认为混合文件 | 一期要求用户拆分文件后重新上传 |
| OCR 失败或内容无法读取 | 显示识别失败，允许重试或更换文件，不将其当作“未找到原文” |
| 未上传某类材料 | 对该材料的必查项展示“未找到：材料未上传”，进入人工确认流程 |

系统不能仅凭“无法确定类别”就断言文件是混合文件，可能还存在清晰度不足、识别失败等原因。后续可增加把源文件交给支持视觉理解的模型辅助分类的路径。

分类纠正后，旧类别生成的结果不继续沿用；重新生成的结果需要重新确认。其他未受影响材料的确认结果保留。此为本稿补充的实现建议，供开发评审采用。

## 5. 核对页结构与滚动

### 5.1 页面结构

左侧为固定导航侧栏；右侧从上到下为任务信息与全局统计、材料导航、一个左右核对工作区、底部“完成核对”。中间工作区在任意时刻只显示一种材料。点击营业执照、公司章程或已审计财报，同时替换左侧原件与右侧检查要点，不跳转到另一张业务页面。取消三类材料纵向堆叠，不再提供材料展开／折叠按钮。

核对页采用视口内布局，无核对页全局纵向滚动；工作区使用顶部和底部之外的剩余高度。长原件、长清单分别在两侧内部滚动。切换材料不能重新识别或重置结果：接受／拒绝选择、拒绝原因、左侧文件／页码／缩放和阅读位置、右侧滚动位置与定位状态均按材料保留，切回后恢复。全局统计始终覆盖所有材料，完成条件同样覆盖全部材料，不能只检查当前可见材料。

V0.4侧栏设置“首页”“我的任务”“资料核对”“材料管理”，高亮当前功能。底部显示当前用户与退出登录，固定设置图标，预留位置，不配置菜单。侧栏与主内容滚动独立；折叠后保留窄图标栏和展开入口，图标提供名称提示。展开时可拖动右边界调整宽度，主内容随之适配；最小／最大宽度按实际布局验证，避免侵占核对工作区。拖动侧栏不得重置摘录选择、输入内容或左右滚动位置。

资料核对、材料管理顶部始终显示当前任务名称／标识与客户类型，并提供任务选择入口。切换到另一任务时替换该功能页的数据，保留当前功能，不先返回任务列表。文件、结果、统计、确认记录与阅读位置按taskId区分；跨功能导航也保留当前taskId。具体保存及状态规则见第12节。

顶部统计固定可见，不随任一材料内部滚动，不遮挡定位目标。统计项为总计、未选择、已接受、已拒绝、接受比例、拒绝比例，并单独提示“拒绝原因待填写”条数。

统计按需确认的结果条数计算：每段原文、每张完整表格、每个印章／签名候选、每条“未找到”结果各计一条。一个图像候选的识别文字与图片合算一条，不重复计数。同一问题的两段原文计两条，标题合并不影响计数。设总数 N、未选择 U、接受 A、拒绝 R，则 N=U+A+R；接受比例=A/N，拒绝比例=R/N，均以总数为分母。N=0 时比例显示“—”，不把无结果视为完成。点击拒绝即计入 R，即使原因未填；原因待填写数单独统计，仍阻止完成。重置选择后相应 A 或 R 减一，U 加一；所有统计随当前结果和操作实时更新，不能固化示例数值。已选择数量=A+R，但不代表全部满足完成条件。

材料导航按钮用于选择当前显示的材料，同时用颜色、文字和数量表达各类材料的核对进度。状态优先级依次为“待补原因”“已核对”“核对中”“未开始”；拒绝本身不触发红色警戒状态。

| 材料核对状态 | 展示规则 |
| --- | --- |
| 有拒绝原因未填 | 橙色，“待补原因 x” |
| 全部选择完成且拒绝原因齐全 | 绿色，“已核对 n/n”，允许存在拒绝项 |
| 已选择部分结果 | 蓝色，“核对中 x/n”，x 为已接受加已拒绝 |
| 尚未选择任何结果 | 灰色，“未开始” |

上述颜色仅表示人工核对进度，不表示合规结论。当前显示的材料另以蓝色描边等视觉方式区分，避免覆盖进度语义。处理失败、上传及识别中的状态仍按第4节单独展示。

选中一种材料后，左侧显示其原件查看器，右侧显示其固定清单和摘录卡片；其余材料不占用工作区高度。

| 滚动区域 | 行为 |
| --- | --- |
| 核对页整页 | 不提供全局纵向滚动；通过材料导航替换显示 |
| 左侧原件 | 独立翻阅、滚动查看上下文，不带动右侧 |
| 右侧摘录 | 独立滚动，不带动左侧 |
| 宽表格内部 | 必要时横向滚动，保留可读的列宽与行列关系 |

右侧相当于稳定的核对清单。只有点击摘录正文／出处时，才主动驱动左侧定位；左侧自由翻页不改变右侧当前摘录、选择状态和滚动位置。

### 5.2 摘录卡片

一个检查项使用一个外框，搜寻要点／问题标题只出现一次；外框内按相关程度排列一条或多条独立摘录。每段摘录均保留自己的原文、文件名、页码、定位入口、确认按钮和拒绝原因，不提供整组一键确认。例如“借款与担保的决议权限／批准机构”只显示一个标题，下方分别展示第十二条和第十八条。

未选择时展示绿色“✓ 接受”和红色“✕ 拒绝”两个互斥按钮，不默认选择。接受后隐藏拒绝按钮，仅保留高亮接受按钮；拒绝后隐藏接受按钮，仅保留高亮拒绝按钮，并在其右侧显示原因输入框。卡片不再额外显示“待确认”“已确认”等状态文字。

所选按钮被鼠标悬停时立即变为另一颜色的“再次点击修改”按钮；移出且未点击则恢复所选状态的文字和颜色。再次点击这个唯一按钮时，将当前条目重置为未选择，恢复接受／拒绝两个按钮，同时隐藏原因框并清空原因内容，无需再次弹窗确认。键盘聚焦时提供同等“再次点击修改”提示，按回车或空格执行重置；触屏环境直接二次点击所选按钮也执行相同行为。这里修改的是确认选择，原文始终只读。

拒绝原因框初始为一行高，随输入文本自动换行并增长为多行输入框，完整保留所填内容。优先放在拒绝按钮右侧，水平空间不足时移到下一行，不遮挡原文、出处或按钮。拒绝原因必填，纯空格视为未填写；清空后重新选择拒绝时，不恢复上一次原因。

文本原样展示；只允许布局换行、空白规范化等不改变含义的处理。摘录不得把分散的内容拼成原文中不存在的新句子。多处来源需要分别标注。

### 5.3 表格

当 OCR 返回 `<table>` HTML 时，右侧渲染为可读表格，保留表头、合并单元格、金额单位及原有行列关系。表格布局随摘录区宽度适配，列过多时允许内部横向滚动，不为适配而重排或省略关键数据。

一张逻辑完整的表格作为一条结果，共用一组接受／拒绝；一期不做逐行或逐单元格确认。若完整表格跨多页，应保留多页来源映射；能否自动拼接取决于现有 OCR 服务，开发联调需验证，无法重组时保留分页展示并说明。

HTML 只用于呈现表格，实施时应清理脚本、事件属性和外部资源加载等内容，避免将 OCR 输出作为任意可执行网页直接嵌入。

### 5.4 印章与签名图像结果

本版财报新增“审计单位印章”和“注册会计师签名”，原有审计机构文字项继续保留。其他材料本轮不新增印章／签名检查项；类型能力可由固定清单后续扩展，不建设清单管理后台。

每个检查项只显示一次标题，下方按候选逐条展示，顺序为：识别文字 → 对应裁剪图 → 文件名／页码及定位入口 → 接受／拒绝。识别文字应区分来自 OCR 还是图像模型；缺乏可靠文字时不得填入猜测姓名或机构名。图像保持宽高比并适配右侧区域，不以拉伸变形替代展示。

每个候选的文字和图片作为一条整体结果确认。多个候选分别确认；拒绝时填写该候选的原因，二次点击重置时清空该原因。文字和图片均不可人工修改。“未找到相关印章／签名”同样作为待确认结果，接受只表示认可查找结果。

#### 查找流程

1. 接收 OCR 检测出的印章／签名裁剪图、对应识别文字及来源映射。为每张图保留稳定 cropId、文件、页码与坐标关联，不能仅凭图片排列位置建立引用。
2. **文字匹配优先**：使用已识别文字匹配固定检查项及目标。例如“审计单位印章”应与材料中提取的审计机构名称相对应。文字足以识别和匹配时，采用相应候选，本项不再调用图像模型。
3. **图像识别兜底**：文字不足以找到或确定对应关系时，把裁剪图交给支持图像理解的模型辨认、区分并匹配检查项。当前不固化候选筛选算法；允许考虑将全部相关裁剪图交给模型挑选。受模型输入限制时，分批处理和汇总属于实现建议，具体单次图片数、大小、批次、停止条件需联调确定，不能擅自把先筛选少量图片作为已确认业务规则。
4. 模型应返回被选 cropId 及识别内容，引用必须落在本次输入图片范围内。可找到多个相关候选并按相关程度排列，不要求强行只选一个。这里只识别内容和对应关系，不判断印章真伪、签名是否本人所签或材料合规性。

#### 结果状态与保守处理

| 情况 | 右侧展示及处理 |
| --- | --- |
| 找到对应候选 | 展示识别文字、图片、出处及接受／拒绝 |
| 找到多个候选 | 同一标题下逐个展示，每个独立接受／拒绝并计数 |
| 已能识别为相关印章／签名，但与具体检查项目标的对应关系仍不确定 | 展示有依据的候选及图片，标注“对应关系待人工核对”，不强行确定 |
| 文字未识别成功，但图像识别能够确定其类型和相关性 | 可展示图片；文字不可靠时标明“文字未能可靠识别”，不猜测文字内容 |
| 文字识别失败，且图像模型也无法判断图片是什么、应归入哪类或哪一检查项 | 保守展示“未找到相关印章”或“未找到相关签名”，仍需接受／拒绝；不把无法归类的图片列作右侧候选 |
| 没有检测到相应候选 | 展示“未找到相关印章”或“未找到相关签名”，仍需接受／拒绝 |
| OCR、图片读取或模型调用发生技术失败 | 显示处理失败，允许重试；不能伪装成正常的“未找到” |

“对应关系待人工核对”要求已有证据支持候选类别或与该检查项的相关性；不能用它绕过“文字和图像均无法归类时展示未找到”的约定。未找到表示本轮处理未找到可对应的结果，不证明材料不存在签章。内部保留识别阶段、失败原因和处理日志，以便复查，但本版不要求把全部无法归类的裁剪图展示给用户。

## 6. 原文定位与高亮

每条摘录关联来源文件、源文件页码和一个或多个 OCR 块。点击摘录时，左侧选择对应文件、跳转到对应页面，把来源区域滚动到可见位置，并按段落／表格／印章／签名区域高亮。右侧位置不变。

段落级坐标足以支持段落框高亮，不承诺字符级高亮。坐标需要结合 OCR 页面尺寸、预览缩放比例和方向矫正信息映射到原件。预览与 OCR 页面尺寸或旋转不一致时，不能直接把坐标当作屏幕像素使用。

同一摘录跨多个块时关联多个框；跨页时标注多个出处并可逐页查看。表格点击定位到表格区域；点击印章／签名图片或出处时，定位到其源文件裁剪区域。未找到结果没有虚构出处，不提供可点击的伪引用。

若坐标缺失但页码有效，则退化到对应页，显示“当前仅能定位到页”；坐标映射失败不改变摘录的人工确认状态。

## 7. 人工确认与完成

| 状态／操作 | 规则 |
| --- | --- |
| 待确认 | 接受／拒绝均未选中，不默认接受 |
| 接受 | 当前条目记录为已接受 |
| 拒绝 | 展开拒绝原因文本框；原因必填，纯空格视为未填写 |
| 原因未填写 | 允许保留当前草稿，但不能完成核对 |
| 拒绝原因已填写 | 当前条目满足完成条件 |
| “未找到相关原文／印章／签名” | 同样必须接受或拒绝；拒绝时填写原因，不能补写摘录 |
| 文字／表格／印章／签名结果 | 始终只读，图像与识别文字不允许人工修改 |

接受表示认可当前摘录或“未找到”的查找结果，不表示企业、材料或本笔贷款通过合规审查。某段被拒绝也不直接等于整个检查项不合规。

完成前若需改变接受／拒绝，先点击所选按钮（悬停时显示“再次点击修改”）重置，再重新选择；重置和清空原因均自动保存，并同步统计及材料进度。过程自动保存，离开后可以继续；保存失败时明确提示，不能显示为已完成。任务完成后仍按只读方式查看，不提供重置操作。

点击“完成核对”时，系统及后端都校验：

- 本轮处理已结束，没有仍在上传、OCR或摘录中的文件；处理失败应单独处理，不能伪装成业务缺口。
- 当前任务所有材料的应确认结果（包括图像候选及未找到结果）已选择接受或拒绝；与当前选中材料无关。
- 所有拒绝结果的原因均已填写。

条件不满足时提示具体缺口，并可定位到待处理位置。条件满足时，即使存在拒绝项或已确认的材料缺口也允许完成；保存后在当前页显示“核对已完成”，本次任务结束，不跳转结果汇总页。完成后默认以只读方式查看；重新打开任务的机制后续再定。

## 8. 开发数据与契约基线

V0.5已把早期示意字段落实为配套开发包的统一snake_case契约。本节解释对象关系；具体类型、枚举、事务、HTTP和数据库约束以开发包docs/03_data_model.md、docs/04_api.md、contracts/openapi.json及Pydantic DTO为准，不再将早期camelCase建议当作接口。

### 8.1 固定清单

清单按version、product_code、customer_role识别，使用contracts/checklist.borrower.v1.json及checklist.schema.json。每类material_type包含检查项id、label、result_mode、group_label、dependencies与required。借款人版本为borrower-wcl-v1；另外两种角色enabled=false，不能复制该版本启用。

### 8.2 数据对象

| 对象 | 核心字段与关系 |
| --- | --- |
| 用户与会话 | user.id、username、password_hash；auth_sessions关联user_id并支持到期/撤销 |
| 任务 | id、owner_user_id、product_code、customer_role、checklist_version、input_revision、current_run_id、state |
| 文件与资产 | task_files.id/task_id、原名、hash、分类；assets保存原件、页面图、裁剪图及原始响应的存储键 |
| OCR来源 | ocr_jobs→ocr_pages→ocr_blocks，保留外部编号、页序、原始label/ID、文字/表格与坐标 |
| 图像候选 | crops.id、task_id/file_id/page_id/block_id、kind、recognized_text、image_asset_id及来源坐标 |
| 处理批次 | processing_runs.id/task_id/input_revision、清单快照、模型与提示词版本、阶段及覆盖状态 |
| 结果与出处 | results.id/run_id/check_item_id/kind；result_sources关联file/page/block及字符范围、坐标或定位降级 |
| 人工确认 | decisions.result_id、decision、reject_reason、version、actor_user_id、updated_at |

未找到是有效查找结果；技术失败、缺坐标、无法确定类别分别记录，不混入同一个布尔值。模型引用只能落在本用户当前批次输入集合内，原文由代码从来源块读取，不采用模型生成的新句子。

### 8.3 图像、持久化及版本

裁剪图与识别文字必须能回到同一来源；合法Base64/data URL解码归档，远程签名URL及时下载归档。只保存外链不满足退出后回看。缺坐标而有可靠页码可降到页定位；页码也不可靠就不能伪造原页引用。

数据库采用PostgreSQL，通过Docker运行；大原件、图片与OCR原始JSON保存在持久化文件目录，由数据库保存关联。文件变更生成新输入修订，旧批次不能覆盖新结果；确认版本用于多窗口冲突保护。任务、文件、结果、图片及保存记录都检查用户归属。

| AC32 | 点击印章／签名图片或出处 | 左侧定位其源页和区域；右侧位置及确认状态不变；坐标不足时按规则降级 |
| AC33 | 当前可见材料已确认，但其他材料仍未处理 | 全局完成校验仍拦截；不能只检查当前材料 |
| AC34 | 图像读取或模型调用失败 | 显示技术处理失败，不能当作正常未找到或缺章结论 |

1. **印章／签名识别服务**：图示用于演示展示和确认，没有实际调用 OCR 或视觉模型，也未验证 Base64 裁剪图的接口和识别精度。文字优先、图像兜底、候选不确定、无法归类后未找到等规则已在第5.4节明确；本轮主画面展示找到图像的示例，不把视觉图示当作识别已实现的证明。
2. **图像输入策略**：候选筛选尚未固化，保留将全部相关裁剪图交给模型挑选的方向。模型输入上限、批次和停止条件待联调，未在原型中模拟实际请求。
3. **真实来源坐标**：现有来源为虚构示例和预置出处框。真实裁剪图与源页、坐标、缩放及旋转的对应关系，跨页表格和多文件切换均需联调。
4. **侧栏连续拖动调宽**：原型已体现折叠和恢复，未实现连续拖宽。
5. **拒绝原因自由输入**：以点击填入预设文本演示单行至多行，不支持自由输入及全部窄屏换行状态。
6. **键盘、触屏及不同视口**：完整键盘聚焦提示、回车／空格操作、触屏等价行为、不同高度下的区域适配需真实前端验证。
7. **状态恢复与业务保存**：原型保留同一材料实例的方式用于演示切换；实际浏览器中页码、缩放、左右滚动位置的完整恢复，以及刷新、离开后继续和持久化保存仍需开发验收。原型未连接真实上传、分类、文件服务、大模型或数据库。
8. **身份认证与隔离**：登录和退出仅演示页面跳转，用户名与密码为预置文本，未实现自由输入、凭据验证、会话、真实账号或后端资源隔离。显示登录页不表示已满足多用户安全要求。
9. **首页上传与新建任务**：点击上传区显示预置文件，清空可恢复；不支持真实文件选择、拖拽、上传、逐文件移除及持久化创建任务。三条任务为示例，不代表已建立三份独立数据库记录。
10. **异步处理**：加载动画及“演示结果就绪”为模拟；没有实际服务回调、自动完成、真实阶段进度、失败与重试逻辑，不把演示按钮作为实际产品功能。
11. **跨任务状态**：顶部选择能改变任务上下文、切换可见内容并保留功能页；原型只完整预置一份借款人结果，未完整演示多个真实任务各自的文件、确认数据、阅读位置及列表状态联动。前端实现必须以taskId隔离状态，不能照搬共用全局变量。
12. **角色清单**：后两种角色的具体业务清单未定，原型仅表达待配置状态；三种角色完整可用尚需分别提供清单。

## 12. V0.4登录、首页与跨任务交互要求

### 12.1 登录及用户隔离

登录页仅保留品牌、用户名、密码及登录按钮。密码默认掩码，眼睛切换显隐且保留当前输入。空用户名／密码不能提交；请求进行中显示按钮加载状态，避免重复提交；凭据无效给出统一失败提示，不跳转。成功后进入首页。无注册、找回密码及账号管理页面。

真实系统必须针对任务、文件、预览／下载、OCR结果、裁剪图、摘录和人工确认的所有接口校验当前用户的资源归属。更换URL中的taskId／fileId或构造直接请求，不能访问其他用户数据；后台处理也按任务及用户关联结果。不能仅用前端菜单、列表过滤或taskId难以猜测作为隔离。

退出登录后清除会话与前端用户缓存，返回登录页；刷新或浏览器后退不能继续读取前一账号数据。密码只存安全哈希，不将API密钥置于浏览器。账号创建、停用和密码重置由本地命令维护，会话默认8小时并支持退出撤销；具体见开发包，不新增管理页面。

### 12.2 首页与任务建立

首页主体采用用户示意图的左右布局：左侧点击／拖拽批量上传，右侧“法人客户类型”单选借款人、保证人、抵（质）押人及“开始核对”。复用成熟上传、单选、表格、表单与加载组件；整体保持现有蓝白工作台风格。首页下方提供继续最近任务入口；没有任务时显示适当空态。

真实前端上传后展示文件名、大小、上传状态与移除入口；同类材料可多份。文件限制以配置为准，不在页面固化未确认上限。本期仅借款人可选；保证人、抵（质）押人置灰且后端拒绝创建，各自预留独立检查清单，不多选、不复制借款人清单冒充其他角色。任务记录其客户类型和清单版本，后续恢复时使用该任务的上下文。

点击开始先校验文件与客户类型；有效时创建／保存任务并直接进入其核对工作台，无处理中间页。后台可以异步处理；工作台有加载动画和阶段说明，材料管理有文件状态。技术失败须区分上传、OCR、分类或摘录失败并允许对应重试；等待中不能先显示“未找到”。尚无全部结果时不能将临时数量作为已最终完成的统计。清单配置缺失时明确提示并阻止假执行，保留已建任务和已上传文件。

### 12.3 我的任务及全局任务上下文

“我的任务”是当前账号任务的最小列表入口，至少展示任务名称／标识、客户类型、处理／核对状态、继续或查看操作，并有新建入口返回首页。处理中的任务打开后仍进入工作台显示处理状态；已完成任务按只读规则查看。任务列表需读取真实状态，不因原型示例显示“待核对”而固定该文字。

资料核对和材料管理顶部放置相同的当前任务选择器，显示可辨认的任务名称／标识与客户类型；打开后只列当前账号的任务。切换任务只替换当前功能页的数据：在资料核对页切换后仍看资料核对，在材料管理页切换后仍看材料管理。侧栏在两个功能间切换时沿用同一个当前任务。任务为空时提供回首页新建的入口，不能展示其他账号或上一次登录的任务。

实现时应先保存当前任务的有效修改，再切换；保存失败时保留当前任务并给出重试提示，不静默丢失原因输入。接受／拒绝、原因、统计、当前材料、文件、页码、缩放及左右滚动位置分别按taskId保存或恢复。异步响应必须关联发起请求的taskId，不得在任务A的晚到响应中覆盖当前任务B；切换页面本身不等于取消后台OCR。以上为前端预期行为，原型尚未完整演示。

## 13. V0.5本轮确认及开发边界（覆盖旧原型）

1. 同时使用人数在5人以内；支持独立账号，不同用户互不可见。不建设共享任务协作、企业组织角色或高并发平台。
2. Figma仅用于表达意图。允许成熟模板和组件优化外观；本说明中的双栏、单工作区、来源定位、逐条确认、统计和任务切换等行为仍需实现。
3. 仅借款人可选和可创建任务。保证人、抵（质）押人按钮保留、置灰、不可点击，提示清单待配置；后端接口同样拒绝。V0.4中可选这两种角色的演示不再是当前软件要求。
4. 任务完成前允许补传、删除、更换文件及纠正分类；产生新输入修订和处理批次，受影响检查项重新生成并重新确认，未受影响材料的有效确认保留。旧批次迟到不得覆盖新结果。处理中旧结果只读，完整新结果发布后可核对；最后一份文件删除回草稿，不按零条完成。
5. 完成后任务与文件均只读，本期不提供重新打开。接受/拒绝不代表合规结论。
6. 账号和外部服务初始配置由本地.env预置，账号用本地命令初始化；不建设注册、找回密码、配置或账号维护页面，设置图标仍占位。
7. OCR沿用已提供公网异步接口，新营业执照JSON已核实包含seal块、文字、坐标、markdown.images图片映射。图片为远程URL，先下载归档；实现同时兼容合法Base64/data URL。签名实际字段及专项识别仍待样本验证，不视为已证明支持。
8. 本期只提取报告年度供人工核对，不自动判断是否满足“最近一年”的合规要求；该年度业务口径后续再明确。
9. 核对同一任务的所有材料。原文只读、结果分组与计数、拒绝原因必填、修改清空、完成后只读等既有约定继续适用。开发包提供机器可读清单与契约，不写死19条。
10. PostgreSQL和持久化文件目录保存任务、文件、处理和确认。默认容器化FastAPI API/worker与数据库，React/shadcn复用官方模板。真实接口、配置、限额、失败恢复、鉴权和验收见配套开发包。本次交付是开发输入，不是已跑通网站。
