# 页面与交互实现规范

Figma只表达意图，允许优化布局、排版、颜色和留白；不能取消核心核对行为。本期以桌面浏览器为主，覆盖Mac/Windows的现代Chrome和Edge。默认中文，使用本地系统中文字体，必要字体随包提供，不依赖外网字体CDN。

## 1. 组件复用

沿用模板React/TypeScript、shadcn/ui、TanStack Router/Query、React Hook Form/Zod。优先使用现有Sidebar、Button、Card、Dialog、Select、Tabs、Tooltip等；上传使用react-dropzone，原因输入使用react-textarea-autosize，PDF使用wojtekmaj/react-pdf（查看现有PDF，不能误用用于生成PDF的@react-pdf/renderer），拖拉布局使用react-resizable-panels，表格HTML用DOMPurify严格白名单。具体包版本由P0兼容验证后锁定。

不要为基础控件逐像素手写一套CSS，也不要同时混入Ant Design和shadcn两套主题。必须编写的业务界面是证据分组、确认状态机、来源高亮和跨任务状态隔离。Tailwind用于组合布局与少量业务样式。

## 2. 页面

| 路由 | 内容 |
| --- | --- |
| /login | 品牌、用户名、密码、小眼睛、登录。没有注册、找回密码、账号配置 |
| / | 首页：左批量上传/文件列表/移除，右客户类型/开始，下方继续最近任务 |
| /tasks | 当前账号任务，名称、类型、状态、更新时间和继续/查看；新建入口到首页 |
| /tasks/$taskId/review | 顶部任务选择、全局统计、材料导航、左右独立滚动工作区、底部完成 |
| /tasks/$taskId/materials | 同一任务选择器，文件、处理状态、纠正分类、补传/更换/删除 |

侧栏：首页、我的任务、资料核对、材料管理；资料核对/材料管理沿用当前taskId。无当前任务时引导首页新建，不随意打开别人的任务。底部固定用户、退出、设置图标；设置仅占位。支持折叠和拖宽（初值220px，展开160–320px，折叠56px，可按实际布局调），不能仅因使用Sidebar组件就宣称已支持连续拖宽。

首页初始borrower可选，另两项可见、disabled，并注明“清单待配置”；鼠标/键盘均不可选，后端capabilities同样enabled=false。用户选择文件后可创建内部DRAFT任务并上传，不显示处理中间页面；开始直接导航review。上传失败的文件显示失败并可移除/重试；仍在上传时开始不可用。

首页新建清除旧上传草稿的界面绑定，不能覆盖既有任务；退出后可从任务列表恢复已保存草稿。任务名称默认“资料核对 + 创建时间”，可在任务列表内改名，不增加企业信息必填表单。草稿继续操作回首页加载该taskId，已开始任务继续进入review。

## 3. 同页处理状态

QUEUED/RUNNING在工作台主体显示加载动画、阶段、文件进度和排队提示。外部OCR有页数才显示已处理/总页，未知时只显示阶段，不编造百分比。分类不确定或技术失败显示对应原因及材料管理/重试入口。已处理旧结果可只读展开并明确过期，不允许继续确认。

未全部完成时统计卡显示“处理中”或占位，不把0/旧结果计数当当前完整结果。READY后加载完整检查组；失败不能显示“未找到相关原文”。关闭浏览器、退出登录、切换任务不会取消后台作业。

## 4. 核对工作区

使用视口高度100dvh。外层不做材料堆叠和全局纵向滚动；header/统计/材料导航/footer固定，内容行min-height:0。左右面板独立overflow，PDF/图片左侧，检查组右侧。建议宽屏55:45，可拖动分隔；最低窗口1280×720仍可操作，窄于此可折叠侧栏并压缩统计，不能遮住操作。移动端不作为本期验收目标。

材料Tab只替换当前工作区，保留每任务每材料的文件、页码、缩放、左右滚动锚点。多份同类文件在左面板顶部提供文件选择器；点击右侧出处自动选对应文件和页。初始按上传顺序显示，同类不丢弃；发现重复内容不静默合并独立来源。宽表格在卡片内部横向滚动。

全局计数取服务端statistics，当前材料之外的结果也计入。材料进度灰/蓝/绿/橙按规范；拒绝本身不是红色材料警报。选中材料用描边/下划线区分，不覆盖进度颜色。完成按钮始终针对整个当前批次，不针对可见Tab。

## 5. 证据卡片与按钮

一个check_item只出现一次标题，内部每段原文/每张表格/每个图像候选各一组操作。图像顺序：识别文字（注明OCR/图像模型）→保持比例的裁剪图→文件页码出处→操作。文字不可靠明确标注，不猜测姓名；not_found无伪造出处。

| 状态 | 按钮与原因 |
| --- | --- |
| unselected | 接受、拒绝两个按钮，均未选中 |
| accepted | 仅高亮接受 |
| rejected | 仅高亮拒绝，右侧出现一行原因框 |
| accepted/rejected悬停或键盘聚焦 | 唯一按钮改为另一颜色“再次点击修改”；移出恢复原选择文案 |
| 再次点击 | 保存unselected，隐藏原因，清空原因内容；无需确认弹窗 |
| COMPLETED/过期批次/处理中旧结果 | 所有确认与重置不可用，允许查看来源 |

原因随输入换行增高；空间不足放按钮下一行。建议maxRows=6后内部滚动，不截断保存内容（最多4000字符）。不额外显示待确认/已确认等状态字样；保存中/失败可以作为临时反馈，不是重复的确认状态。

选择即时发请求，原因输入停止500ms后保存；失焦、切换任务/材料、完成前立即flush。键入时本地保留草稿，保存失败不清空。单条写请求串行使用最新decision.version，避免accept与reset乱序；失败后回滚到已保存状态并保留尚未保存原因。完成按钮等待全部保存成功；不能把乐观UI当已持久化。

## 6. 跨任务与缓存

任务选择器位于review和materials顶部，可搜索当前账号任务；切换后保持review或materials路由功能段。先flush当前原因；失败阻止静默切换并允许重试或明确放弃未保存草稿。Query key至少包含userId/taskId/runId/materialType；禁止只用materialType缓存。

网络请求包含task/run；旧请求取消或忽略，晚到响应只能更新对应缓存，不能写入当前任务。退出清空QueryClient、当前任务指针和用户阅读缓存。允许按userId/taskId保存本地阅读位置，但不得把真实结果/图片Key保存在跨用户共用缓存中；服务端view-state支持刷新与再次登录恢复。

412冲突显示“该条目已在其他窗口更新”，取回服务端状态，让用户决定是否重新操作；不能自动用旧原因覆盖。五个人通常是不同账号，不建设共享任务协作锁或分工页面。

## 7. 来源定位

react-pdf提供PDF渲染，来源层由本应用实现。使用PDF.js viewport/rotation变换，不能只把OCR bbox直接乘固定比例。OCR输入图片若与原PDF旋转/去畸变后不一致，可切换显示已归档OCR页面图，在同一像素坐标空间定位，并标明“OCR处理页”。保留查看原件入口。

只有证明坐标空间一致才画区域框。缺变换/尺寸但页码可靠时定位页并提示“当前仅能定位到页”；页码映射也不可靠时不伪造原件页码。未找到结果不可定位。左侧自由滚动不带动右侧，右侧定位操作也不重置确认与阅读状态。

## 8. 截图参考与验收

assets/ui包括登录、首页、任务列表、核对、材料管理及财报图像结果的历史原型。允许改进视觉；新版禁用角色、真实保存反馈和技术错误状态以文字规范为准。开发后至少提供1280×720、1440×900、1920×1080截图并实际检查原因长文本、宽表格、长清单、双栏滚动和侧栏拖宽。
