# 章程核对验证

用 [根 README](../../../README.md) 启动静态原型。原始公开 15 页样本固定在 V1 SHA，当前线框取第 14、15 页的局部摘录和对应的坐标线框，后续联调再验证原 PDF 的定位。可通过场景选择切换处理中、缺材料、两类覆盖不全与完成只读。

本文分两段：**第一节 本轮已实测**（阶段 A，浏览器验收）、**第二节 阶段 B 待验**（后端联调验收）；**第三节**列待产品确认的开放项。结论标注〔本轮实测〕/〔历史沿用〕/〔尚未验证〕，并附命令或证据路径。

## 一、本轮已实测（阶段 A，浏览器验收）

预览命令：

```bash
python3 -m http.server 8092 --bind 127.0.0.1 --directory credit-review-app-v2/prototype
```

浏览器 <http://127.0.0.1:8092>。验收环境：真实 Chrome（chrome-devtools MCP），视口 1440×900。〔本轮实测〕

| # | 验收项 | 操作 | 实测结果 |

### 独立复验（本轮实测）

上表结果由编写代码的会话自测。为排除自测偏差，另起一个**独立浏览器会话**（`browser_use` 子 Agent，与编写会话分离）对同一份线框复跑，六项全部 PASS：

| # | 复验项 | 独立会话结果 |
|---|---|---|
| 1 | 控制台与资源请求 | 无任何 JS 控制台错误；favicon 请求消失〔本轮实测〕 |
| 2 | 顶栏元素 | 任务名、客户角色、输入版本 `v1`、状态徽标、进度、完成核对按钮与原因齐全，与自测一致〔本轮实测〕 |
| 3 | 六场景表现 | 两个覆盖不全场景的受影响项集合不同；只读态仅剩「查看出处」与选中动作〔本轮实测〕 |
| 4 | 完整路径 | 下一条待办 → 查看出处「已定位第 14 页」→ 拒绝（空格禁用 / 非空启用并保存）→ 逐项接受至 4/4、原因「可完成」→ 完成 → 只读 → 刷新后决定与拒绝原因保留〔本轮实测〕 |
| 5 | 左栏控件 | 翻页、页码输入、缩放档位可用，页脚边界标注在位〔本轮实测〕 |
| 6 | 样式稳定性 | 六场景切换下字号、间距、状态色、按钮层级无跳变〔本轮实测〕 |

复跑方式见 [验收 Skill](../../../.trae/skills/charter-workbench-acceptance/SKILL.md)。

## 二、阶段 B 待验（后端联调验收）

四个用例：正常完成、非法出处、输出截断、原件定位。契约以 [api-contract.md](../architecture/api-contract.md) 为准，落库口径以 [data-dictionary.md](../architecture/data-dictionary.md) 为准。**V2 后端、数据库与接口目前都不存在**，下列预期是阶段 B 的验收目标，不是当前事实。

| 用例 | 目标 | 预期 HTTP | 预期数据库 | 三条证据的落点 |
|---|---|---|---|---|
| B-1 正常完成 | 覆盖完整且全部摘录已决定 | `POST /complete` → `200`，返回 `{state, statistics}` | `tasks.state = 'COMPLETED'`、`tasks.completed_at` 非空、`tasks.last_ready_run_id` = 本次 `run.id`，三者在同一事务内提交 | E-1 按钮可点；E-2 真实 200；E-3 三个字段确实写入 |
| B-2 非法出处 | `coverage_complete = false`，受影响项存在 | `POST /complete` → `409 COVERAGE_INCOMPLETE` | `tasks` 行逐字段不变（零写入）；`decisions` / `decision_events` 不新增 | E-1 按钮禁用且原因列出受影响项；E-2 真实 409；E-3 零写入 |
| B-3 输出截断 | 与 B-2 同源、受影响项集合不同 | `POST /complete` → `409 COVERAGE_INCOMPLETE` | 同 B-2 | 同 B-2 |
| B-4 原件定位 | 点出处 → 左栏定位并高亮 | 无写接口；读接口须返回 `source_page_number` / `bbox` / `page_width_px` / `page_height_px` | `ocr_pages.source_page_number` = 上传文件物理页号、`mapping_status = 'verified'`、`raster_asset_id` 非空 | E-1 浏览器定位到同一页并画出框；E-2 接口字段正确；E-3 库内页码映射已验证 |

**三条独立证据**（缺一条不算通过，且三条必须指向同一 run、同一批数据）：

| # | 证据 | 判定方式 |
|---|---|---|
| E-1 | **前端按钮禁用** | 在「覆盖不全」「未确认」「拒绝缺原因」「资料已变更」四种情形下，界面上的「完成核对」呈禁用态，且禁用原因文案与 `completion.reason_text` / 错误码语义一致 |
| E-2 | **实际 HTTP 响应** | 用同一 run 真实发起 `POST /api/v2/tasks/{task_id}/complete`，得到对应 `409` 与契约错误码；不得用构造响应或 mock 代替 |
| E-3 | **数据库写入状态** | 前后读取 `tasks` 同一行的完整快照逐字段比对，确认零写入；并确认 `decisions` / `decision_events` 无新增行（对 `INVALID_DECISION` 用例） |

零写入判定沿用 V1 `tests/perf/run_complete_http.py:112-130` 的前后快照法〔历史沿用〕。

## 四、尚未验证

1. 真实 PDF 的页码定位与高亮精度（当前只有文字坐标线框；缩放、定位与高亮精度在阶段 B 用本地批准样本验证）。
2. `source_page_number` 与上传文件物理页号的一致性（V1 从不验证，`mapping_status` 恒 `unverified`）〔历史沿用〕。
3. 缺材料场景下 `POST /complete` 的实际响应体与错误码（待第三节开放项 2）。
4. 受影响项在「覆盖不全」场景下的决定写入路径：线框当前**不提供**接受/拒绝入口〔本轮实测〕，接口层是否允许写入待产品确认。
