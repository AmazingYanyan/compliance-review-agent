### 传输层故障与本地绕过（本轮实测）

`git fetch` 首次失败，报 `Error in the HTTP2 framing layer` 与 `Failed to connect to github.com port 443 after 75003 ms`。`GIT_CURL_VERBOSE=1` 显示 git 解析到 `20.247.166.64:443` 直连超时，而 curl 解析到 `20.6.7.17` 可连通，属 DNS 多址中部分地址不可达。

绕过（仅本地 `.git/config`，不进提交）：`git config http.curloptResolve "github.com:443:20.6.7.17"` 且 `git config http.version HTTP/1.1`。地址可能随 DNS 轮转变化，接手时若再次失败请重新解析可用 IP 后覆盖该配置。

**收尾更新〔本轮实测〕**：本轮提交时该固定 IP 已失效（`Empty reply from server`），而 DNS 当下解析到的 `20.247.166.64` 恢复可达。已 `git config --local --unset http.curloptResolve` 撤销固定 IP，恢复默认解析后 `git push` 成功。**结论：不要把 IP 长期固定在本地配置里**，失败时先 `dig +short github.com` 与 `curl -s -o /dev/null -w "%{remote_ip}" https://github.com/` 判定当下可达地址，再决定是否临时固定。

## 二、浏览器基线实测与缺陷清单（本轮实测）

预览命令：`python3 -m http.server 8092 --bind 127.0.0.1 --directory credit-review-app-v2/prototype` → <http://127.0.0.1:8092>

改造前实测通过的行为（须保持）：

- 六种场景切换正常，横幅文案随之变化。
- 「下一条待办」序列实测为 e3 → e4 → not-found → 回绕到 e3，跳过已处理项、到末尾循环。
- 拒绝流程：点「拒绝」出现原因输入框并自动聚焦；内容为空白或纯空格时「保存拒绝」保持禁用，填入非空文本后可保存，决定与原因写入浏览器本地存储。
- 点「查看出处 · 第 15 页」后左侧滚动到对应页并画出高亮，页码显示「已定位第 15 页」。
- 全部确认后计数为 5/5，「完成核对」可用，完成后进入只读态并显示历史决定与拒绝原因，刷新后仍在。

改造前实测发现的缺陷（本轮修复对象）：

1. 两个覆盖不全场景的卡片完全相同，受影响项无法区分，只有横幅文案不同。
2. 顶部没有任务身份与状态，只有场景下拉与完成按钮。
3. 卡片本体不可点击，点击检查项与点击出处的行为没有区分。
4. 完成入口被禁用时不说明原因。
5. 左栏没有跳页与缩放控件。
6. 样式表全是裸数值，字号、间距、状态色、按钮层级没有共用定义。
7. 处理中与缺材料场景只给一句话，没有阶段、进度或补传入口。
8. 只读态未区分「正常未找到」项，计数口径把未找到项算作已确认。

## 四、浏览器复验结果（本轮实测）

Chrome 经 chrome-devtools MCP，视口 1440×900，六场景逐项读取 DOM：

- 正常核对：进度「已确认 0 / 4 · 未找到 1 项待确认」，完成原因「无法完成：仍有 4 项摘录未确认、1 项未找到待确认」，两者口径一致。

- 缺材料：徽标「缺材料」，横幅「缺少材料：公司章程」，右栏给出补传占位入口并标注完成规则待决策，完成原因「无法完成：材料缺失，完成规则待决策」。

语法检查 `node --check` 两个 JS 模块通过；控制台除原先的 favicon 404 外无报错，补 `data:` favicon 后归零。
